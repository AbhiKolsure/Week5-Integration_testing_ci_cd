This Week 5 educational internship project extends an inherited FastAPI task-management backend with authentication, integration testing, regression coverage, GitHub Actions CI, and a simulated deployment validation stage. The project brings together API routes, request and response schemas, authentication dependencies, database sessions, ORM models, CRUD operations, and HTTP error handling. Integration testing is important here because individual modules may work alone while failures can still occur when a user request crosses authentication, validation, persistence, and response layers.

Account registration validates user input and stores passwords as Argon2id hashes rather than plaintext. Login verifies credentials and issues a signed, expiring JWT bearer token. Protected task and comment APIs reject missing, malformed, expired, or invalid credentials. Public responses do not reveal password hashes, and invalid login responses use a generic error. The signing secret is supplied through runtime configuration and is not committed as a real credential.

The integration test suite uses FastAPI TestClient with isolated in-memory SQLite databases. It covers registration, duplicate accounts, successful and unsuccessful logins, password-hash persistence, token claims and expiry, invalid bearer tokens, protected APIs, and task/comment lifecycle operations. Regression tests verify inherited API behavior, including validation, filters, missing resources, and task/comment interactions. Local verification reported 125 passed tests with 2 deprecation warnings, 17 authentication integration tests passed, and 8 regression tests passed. Ruff static analysis passed.

GitHub Actions is configured for pushes to `main` and pull requests targeting `main`. It installs dependencies, runs Ruff, and executes the full pytest suite. The simulated deployment job depends on successful CI and validates required files, application import, startup, and health without deploying to production or contacting cloud infrastructure. GitHub Actions run 37741348125 completed successfully; both CI and Simulated deployment jobs succeeded. The CI-to-simulated-CD gate passed.

Security validation checked secret patterns, environment-file handling, workflow permissions, and ignore rules. It found no suspicious credentials in tracked content. The Week 4 performance evidence remains preserved in the isolated Week 5 repository; expensive load tests were not rerun. The final project and report are available at https://github.com/AbhiKolsure/Week5-Integration_testing_ci_cd. This is an educational project and simulated deployment exercise, not a production deployment or production-capacity claim.
