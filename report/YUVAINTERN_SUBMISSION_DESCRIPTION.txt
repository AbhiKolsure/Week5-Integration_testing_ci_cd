This Week 5 project extends an existing FastAPI task-management backend with
authentication, integration testing, and a simulated continuous integration
and deployment pipeline. The work focuses on verifying that the API routes,
validation layer, authentication dependencies, database persistence, task
and comment operations, and HTTP error responses function together.

Account registration validates and normalizes email addresses and stores
passwords as Argon2id hashes rather than plaintext. Login issues a signed,
expiring JWT access token. The signing key is provided through runtime
configuration, checked for minimum length, and the example placeholder is
rejected. Authenticated task endpoints reject missing, malformed, expired, or
otherwise invalid tokens. Public user responses do not expose password hashes,
and invalid login responses do not reveal whether an account exists.

The integration tests exercise the application through HTTP using isolated
in-memory SQLite databases. They cover registration, login, duplicate
accounts, request validation, password persistence, token validation, task
creation and modification, filtering, statistics, comment creation/listing,
deletion, and expected error responses. Existing regression tests protect
previous task API fixes. The complete locally run pytest suite reported 125
passed tests; the focused authentication suite reported 17 passed, and the
regression suite reported 8 passed. Two existing test-client deprecation
warnings were reported and did not fail the test runs. Ruff static analysis
reported that all checks passed.

The GitHub Actions workflow is configured to run on pushes to the main branch
and pull requests targeting main. It installs the project's requirements,
runs Ruff, and executes the complete pytest suite. Its simulated deployment
job depends on CI success and validates required files, application import,
startup, and the health endpoint. The simulation uses only a temporary local
SQLite database and an ephemeral generated key. It does not deploy to
production or contact cloud infrastructure.

Local HTTP smoke tests exercised application health, registration/login,
authenticated task and comment operations, validation, and error handling.
The simulated deployment completed successfully in local validation. The
project has no configured GitHub remote, so GitHub-hosted workflow execution
has not been verified. This submission includes the project documentation and
actual validation evidence, and makes no claim of remote CI success or real
production deployment.
